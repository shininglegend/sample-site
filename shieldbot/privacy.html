Privacy Policy — ShieldBot

Last updated: 2026-07-22

ShieldBot (“the bot”, “we”, “us”) is a Discord moderation and logging bot. This policy explains what personal data the bot collects, why, how long it is kept, who it is shared with, and the rights you have over it.

By adding ShieldBot to a Discord server, or by remaining in a server where it is installed, you and the server’s administrators agree to the handling of data described below.

Who is responsible for your data

  • Bot operator / data controller: the individual or organisation running this instance of ShieldBot and holding its bot token.
  • Server administrators (per-server controllers): the administrators of each Discord server (“guild”) that installs the bot decide which logging, moderation, and AI features are enabled and where logs are sent. They are jointly responsible for how the bot is used in their server.
  • Contact: If you are using ShieldBot with User ID 1271674557073199175 on Discord, you may contact privacy@shininglegend.xyz for help with privacy concerns. Otherwise, you are responsible to obtain the contact information of the data controller yourself. Check with the server administrators — they will know who the bot operator is.

If you self-host ShieldBot, you are the data controller for your instance and should adapt this policy (especially the contact details and any retention changes) accordingly.

What data we process

ShieldBot only receives data through Discord and only acts on servers where it has been installed. The data below is grouped by feature. Most features are opt-in per server and configured by that server’s administrators; the AI features are additionally opt-in per user.

1. Configuration data (always stored)

Stored in a local SQLite database for the bot to function:

  • Discord identifiers: server (guild) IDs, channel IDs, role IDs, and — where relevant to a feature — user IDs.
  • Server settings: logging channels, automod keyword filters and weights, exempt/isolation roles, ignored channels, ticket configuration, and a logging webhook URL you provide.

2. Moderation & logging data

When a server enables logging, the bot captures moderation-relevant activity and sends it to the server’s configured log channel or webhook. This can include:

  • Message deletions: the message author, channel, who deleted it (where known), the deletion reason, the full message content, and any attachments (re-downloaded and re-posted into the log). Bulk deletions produce a text transcript of the affected messages.
  • Message edits: the author, channel, and the before/after content.
  • Member activity: joins (with account-creation date, the invite/inviter used, member count), leaves, kicks, and bans (with account age, join date, the responsible moderator, reason, and the member’s roles at the time).
  • Moderation actions: bans, timeouts, and manual moderation log entries (target user, moderator, reason).

To make delete/edit logging possible, recent message content and metadata are held temporarily in memory (not written to the database) for up to 24 hours and are lost when the bot restarts.

Log output is delivered into the Discord channels/webhooks chosen by each server’s administrators. Once delivered, that content lives in Discord under Discord’s control and the server’s control, not the bot’s database.

3. Support tickets

If a server uses the ticketing feature, the database stores: the ticket opener’s user ID, the assigned/closing/deleting staff user IDs, the ticket status, and any rating and free-text feedback comment you submit. Deleting a ticket marks it closed but retains the record.

4. Role backups (isolation feature)

When the isolation/restore feature removes a user’s roles, the removed role IDs are stored against that user’s ID so they can be restored, and are deleted once the roles are restored.

5. AI assistant features (double opt-in)

ShieldBot includes an optional AI assistant powered by Anthropic (Claude). It is off by default and only responds when all of the following are true: the server has enabled AI, the bot operator has approved AI for that server, and the individual user has opted in. Users who have not opted in receive a one-time disclosure and get no AI reply; their messages are redacted before any AI processing.

When an opted-in user mentions the bot:

  • Sent to Anthropic: a transcript of up to the 50 most recent channel messages (trimmed to ~6,000 characters), containing display names/usernames and message content; the mentioning user’s message, nickname, and server roles. Messages from users who have not opted in, or who are AI-banned, are redacted before sending. Raw user IDs are replaced with display names.
  • Stored in the database (ai_logs): the bot’s own AI response text, the server and channel names/IDs, the responding user’s ID, and a message link. This is retained for safety review and auto-deleted after 30 days.
  • AI memory (separate second opt-in): if you additionally opt in to memory, the bot may store short factual notes and style preferences about you (capped in number and length) to personalise replies. The extraction process is instructed to exclude special-category data (e.g. religion, health, sexuality, race, politics, precise location) and information about third parties. Memory entries expire after 30 days.

Anthropic processes this data as our sub-processor under Anthropic’s own privacy terms and, per those terms, does not use it to train models. See anthropic.com/legal/privacy.

6. Diagnostics

Operational errors are written to local log files and may be reported to a private developer error channel. These reports can include contextual identifiers (such as a user tag or ID) needed to diagnose the problem.

Data we do not collect

  • We do not collect payment information.
  • We do not sell or rent personal data to anyone.
  • We do not use your data for advertising or profiling beyond the optional AI memory feature described above.
  • Message content is not sent to any AI provider except for opted-in users who mention the bot, as described in section 5.

Legal bases (GDPR)

Where the GDPR applies, we rely on:

  • Legitimate interests — server moderation, logging, abuse prevention, and keeping the bot secure and functional.
  • Consent — the AI assistant and AI memory features, which require explicit per-user opt-in and can be withdrawn at any time.
  • Contract / legitimate interests — providing the ticketing and configuration features requested by the server.

Your rights and how to exercise them

Depending on your jurisdiction (including under the GDPR and UK GDPR), you may have the right to access, correct, delete, restrict, or object to the processing of your personal data, and to withdraw consent.

You can exercise several of these directly through the bot:

  • /ai optin / /ai enable — opt in to the AI assistant.
  • /ai optout / /ai disable — opt out of the AI assistant; this also disables AI memory and deletes your stored AI memory.
  • /memory enable / /memory disable — control AI memory specifically.
  • /memory forget — delete all of your stored AI memory immediately.
  • /ai logs, /ai view, /ai status — see what has been logged and remembered about you.

For requests the commands don’t cover — including deletion of your AI response logs (ai_logs) before the 30-day window, or any other access/erasure request — open a support ticket in the relevant server or contact the operator at the address above. We aim to respond within a reasonable time and, where required, within one month.

Note that some data (such as delivered moderation logs sitting in Discord channels) is under the control of Discord and the server’s administrators; requests about that data may need to be directed to them.

Data storage and security

Data is stored in a local database on the operator’s infrastructure. Access to the bot’s data and administrative/developer commands is restricted to the bot operator. No system can be guaranteed perfectly secure, but we take reasonable measures to protect the data we hold.

Children

Discord requires users to meet a minimum age (13, or higher in some regions). ShieldBot is not intended for anyone below Discord’s minimum age, and we do not knowingly process such users’ data.

Third parties

  • Discord — the platform the bot operates on. Your use is also governed by Discord’s Privacy Policy: discord.com/privacy.
  • Anthropic — AI sub-processor for the optional AI features only: anthropic.com/legal/privacy.
